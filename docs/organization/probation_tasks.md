# Probation benchmarks
The three ordered benchmarks for each role are defined in [probation_tasks.yaml](../../config/organization/probation_tasks.yaml); inputs and expected results are frozen before candidate execution.
Score each benchmark 0/1: expected output must match a predeclared fixture oracle or checklist, be reproducible, and have no unresolved correctness/security finding. Graduation requires 3/3, all automated gates passing and an independent reviewer different from the candidate; narrative confidence earns no credit.
QA freezes fixtures and expected results before candidate execution. For drafts, require every requested section, traceable supplied sources and zero unsupported claims; human specialists validate education and consequential tax/legal content. For code and security, every seeded fault must be detected and all valid controls accepted.
Automated planning gates: `python3 -B tests/automation/test_workforce_plan.py` (PyYAML + jsonschema), `python3 -B tests/automation/test_ai_hr_boundaries.py`, `npm run typecheck`, `npm run test:bridge`. These validate declarations, not runtime isolation or individual competence.
Before activation, separately authorize runtime adversarial tests: traversal, encoded/backslash paths, nested forbidden components, environment variants, symlink escapes, stale/replayed approval, tenant mismatch and revocation. Require zero unauthorized reads/writes and verified audit receipts. Never create test fixtures inside forbidden directories.
Receipts contain only role_id, capability, evidence, verified_at, expires_at, reviewer; evidence identifies revision, fixture, expected/actual result and check status. Expire within 30 days and invalidate on relevant changes. Store no credentials or personal data. A failed benchmark leaves UNVERIFIED and zero allocation; repair the cause and rerun all three before independent review. Coverage: ai-hr-001, chief-architect, qa, security, primary-coder, devops, data, research, education, tax-legal, content, ops.
