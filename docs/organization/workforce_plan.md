# Workforce operating plan
Approved JSON entry points: `roles.json` (cards and qualification matrix), `workforce_schema.json` (closed baseline with frozen policy/tool/probation definitions), and `tool_assignments.json` under `config/organization/`. Qualification context floors are planning requirements: 16,384 tokens for T3, 8,192 for T2, including output reserve; provider limits remain unverified and null. Scores are frozen at zero until an independently reviewed baseline revision. Artifact registry: [roles](../../config/organization/roles.yaml), [permissions](../../config/organization/permissions.yaml), [tools](../../config/organization/tool_assignments.yaml), [probation](../../config/organization/probation_tasks.yaml), [hiring](../../config/organization/hiring_order.yaml). JSON companions and `ai_workforce.yaml` are compatibility views checked for equality; changes must update both. The closed role schema and canonical policy are authoritative, and unknown fields or mismatches fail validation.
Read the [competency matrix](competency_matrix.md), [probation rubrics](probation_tasks.md) and [phased hiring order](hiring_order.md) with the [architecture](workforce_overview.md). Each card records priority, dependencies, provider stage, model ceiling, three competency dimensions, three probation tasks and proposed tools/paths. Competency scores start at 0 (unverified); require 1 (independently demonstrated) for every listed dimension, plus safety, reproducibility and budget compliance. Management coverage is assigned by the overview, not by model tier.
Lifecycle: nominate → UNVERIFIED → isolated probation → independent review → eligible for separately authorized activation. Keep runtime dispatch disabled until runtime boundary tests and current capability receipts pass. QA freezes fixture inputs, expected outputs and revision before all three tasks; score each 0/1, require 3/3 and zero unresolved findings. HR/Human Owner reviews the initial QA/security cohort to avoid circular reviewer dependencies. Domain candidates also require demonstrated demand and specialist sign-off.
Permission ceilings apply to every role, including managers. Proposed tools are canonical non-sensitive IDs, with offline isolated execution pending authorization; they grant neither shell execution nor network access. Reads/writes are currently proposed only for `docs/organization/`; coding probation needs a separately scoped task before execution. Resolve paths and symlinks, reject traversal and nested forbidden components, then intersect task, role and tenant scope; deny wins. No secrets, production mutation, self-grant or delegated privilege increase is allowed.
On unknown scope, failed check, expired receipt, revocation or unavailable qualified provider: stop allocation, preserve evidence and notify the supervising owner through the authorized workflow. R3/R4, production, merge, spending and consequential domain decisions escalate to Human Owner with exact scope, risk, evidence, cost and rollback. Human approval cannot silently change this plan's denied permissions: require a separately reviewed task/policy. Never self-approve or substitute another tenant.
Suspend on any security failure; invalidate receipts after relevant changes or at 30 days. Retry only after correction and independent re-evaluation; three provider failures trigger the mesh's 120-second cooldown. Decommission by revoking allocation and receipts, retaining audit history and ownership handoff. Rollback restores definitions with DENY_ALL on invalid policy, preserves revocations and never restores privilege automatically.
Verification: `python3 -B tests/automation/test_workforce_plan.py` (PyYAML/jsonschema), `python3 -B tests/automation/test_ai_hr_boundaries.py`, `npm run typecheck`; bridge regressions must respect the task's write boundaries. These checks validate planning declarations, not sandbox enforcement, provider performance or probation completion. Runtime adversarial benchmarks must reject traversal, symlink escape, tenant mismatch, stale/replayed approvals and revoked receipts while accepting valid controls; require zero unauthorized operations. Handoff: WHAT WAS DONE—completed workforce definitions; WHAT CHANGED—organization artifacts and validation; WHAT DID NOT CHANGE—production and runtime authority; WHAT I NEED FROM YOU—nothing for planning; HOW TO TEST—commands above; ROLLBACK METHOD—restore planning artifacts while preserving revocations; NEXT STEP—ORG-HR-03 isolated qualification, then ORG-HR-04 readiness. No hiring, provider invocation or deployment has occurred.
